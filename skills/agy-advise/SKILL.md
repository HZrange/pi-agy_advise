# agy-advise

agy 是本机最强的模型。把它当**独立评估者**，不是**选项打分器**。

## 一句话原则

把开放的问题丢给它，让它自己划定方案空间。任何"我已经想好 2–3 条，你选一条"的问法，都是在用它最弱的能力（在别人给定的集合里排序）换掉它最强的能力（自己发现你没想到的解）。

## 什么时候问

- 架构方向、分层、取舍：还没写代码或写了一半都可问
- 卡住超过一轮：说明 Pi 自己的假设可能已经错了，需要不共享前提的第二个脑子
- 破坏性改动前：删表、改协议、迁移数据
- 需要独立审查：Pi 自己给出的方案，再让 agy 从零看一遍

## 什么时候不问

- 事实类问题：文件里写了什么、某个 API 签名 —— 直接读，问 agy 等于让它重读一遍并计费
- 一行就能改的语法/拼写错误
- 连续工具循环里：每次调用 20–130 秒，放进去只会拖慢

## 提问四段式

按这个结构写 `question`，缺哪段就说明你为什么不知道：

1. **目标**：最终要让什么成立（不是"我想改 X"，是"X 之后要满足什么"）
2. **约束**：不能动的接口、兼容性、既有决策、时间盒
3. **已尝试**：做过什么、为什么放弃（每条一行）
4. **失败现象**：具体报错、错误数据、异常行为的原样文本

不写结论。不写"我倾向于 A, 但也可能 B"。前者让 agy 变橡皮章，后者直接坍缩成选择题。

## 反模式对照

| 坏 | 好 | 差在哪 |
|---|---|---|
| "有三个方案：A 加缓存、B 改索引、C 异步化，选哪个？" | "查询在 5 万行时 p99 到 800ms，读多写极少，不能改表结构。已排除缓存（数据每日全量刷新）。这种情况该怎么解？" | 前者把方案空间锁死在你已知的三条里；后者交给它 `find` 与 `rg` 去发现第四种 |
| "我觉得应该加锁，对不对？" | "并发写同一 SKU 时偶发 lost update，见 trace.md 第 12 行。现有代码没有任何同步。风险点在哪，该在哪一层加？" | 前者只要一个 yes；后者要机制 |
| 把 Pi 的整段推理粘进 `context` | `context` 只给事实：路径、报错、约束、已排除假设各一行 | agy 不需要看你怎么想的，那会把它的思路锚死 |
| 让它"确认 src/store.py 里有没有锁" | 先自己 grep，再问"少了这把锁会导致什么" | 前者浪费一次 100 秒的调用 |

## 参数

- `question`：自包含。agy 看不到 Pi 的对话历史，第一条尤其如此。
- `context`：只放 agy 看不到的事实，控制在 10 行内。省 token 也减少锚定。
- `timeoutMs`：默认 240000。要它读 4 个以上文件时给 300000。
- `skipPermissions`：**默认不要传**。只在 `permissions.allow` 没配好又急着要结果时当应急开关；传了它，agy 就能跑任意命令、也能改工作区文件。

## 出错排查

| 现象 | 原因 | 处理 |
|---|---|---|
| `agy returned an empty response (process exit 0...)` | headless 下某工具需要批准，被 soft-deny，整轮取消 | 看错误里的 stderr；把对应命令加进 `~/.gemini/antigravity-cli/settings.json` 的 `permissions.allow` |
| `agy planner timed out` | 问题太大或多文件读取过多 | 拆小问题，或提高 `timeoutMs` |
| `agy ERROR: ...` + exit 2 | 会话内发了斜杠命令（`/model`、`/usage`） | 不要在 stream-json 会话里发斜杠命令 |
| 连续两次拿到同样的泛泛建议 | 问题太抽象 | 补失败现象与约束，给具体路径 |

## 成本

- 简单问答 20–40 秒；读 3–5 个文件的分析约 100–130 秒
- 同一 Pi 会话内连续提问会复用 agy 的会话与 prompt cache，实测第二轮 `cache_read_tokens` 约占总量 91%
- `/reload` 或空闲 10 分钟后 agy 会话会重开，下一次提问重新建立上下文，第一条务必自包含
